> 适用：所有写代码、写文档、写界面文案的人（目前主要是你自己，以及未来的贡献者）

**为什么要有这份文档**：这个项目有三套命名同时在用（`chaos-*` / `Hundun-*` / `馄饨*`），
同一个概念在桌面端叫"卡带"、在站点叫"插件"，同一个 `status` 字段在五张表里含义各不相同。
不钉死这些，每写一个新模块就会再分裂一次。

## 1. 命名硬规则

**规则 N1（最重要）：新代码、新文档、新界面文案一律用 `Hundun*` 品牌名。**

`chaos-*` 只作为**既有仓库路径的历史遗留**存在，允许继续用，**但不再新增任何 `chaos-` 命名的仓库、目录、包名、类名**。

| 场合 | 应当使用 | 不得使用 | 说明 |
| --- | --- | --- | --- |
| 对外品牌 | `Hundun Lab` / 馄饨 lab | Chaos Lab | README、页头 Logo、站点标题 |
| 桌面端产品 | `HundunDesktop` / 馄饨桌面 | Hundun Lite（旧名，已废弃） | 种子数据 slug 为 `hundundesktop` |
| 新增仓库 / 目录 / 包 | `hundun-*` / `com.hundunlab.*` | `chaos-*` / `com.createpen.*` | 包名已统一为 `com.hundunlab.site` |
| 既有 Gitee 仓库路径 | `chaos-lab`、`chaos-lite` | —— | 历史遗留，不改（改了要动远端与本地 clone） |

| 数据库名 | `hundun_lab` | —— | |
| 主题标识 | `hun-tun-yellow` / `hun-tun-dark` | `light` / `dark` | 与桌面端主题名对齐 |
| 前端存储键 | `hundunlab.token` / `hundunlab.theme` / `hundunlab.locale` | `token` | 旧层曾混用 `token`，已在 M0 清理 |

**规则 N2**：文档编号 `docs/NN-名称.md`，`00` 为冻结的历史文档，`01` 为准绳，其余按主题递增（见 §7）。

## 2. 术语词典

### 2.1 产品与内容

| 术语 | 英文 / 标识 | 含义 | 易混点 |
| --- | --- | --- | --- |
| 软件 | Software / `software` | 馄饨系列里的一个产品。当前仅 HundunDesktop | ≠ 插件 |
| 版本 | Release / `software_release` | 某软件的一个版本，由 `version` + `channel` 唯一确定 | **没有 `is_latest` 字段**，最新版按 `published_at` 倒序推导 |
| 安装包 / 资产 | Asset / `release_asset` | 一个版本下「某平台 + 某架构 + 某格式」的具体文件 | ≠ 版本；一个版本可有多个资产 |
| 通道 | `channel` | `stable` / `beta` | 同版本号不同通道是两条不同记录 |
| 平台 | `platform` | `win32` / `darwin` / `linux` | 取自 Node 平台标识，桌面端与站点共用 |
| 架构 | `arch` | `x64` / `arm64` | |
| 包格式 | `package_type` | `nsis` / `appimage` / `deb` / `dmg` / `zip` | |
| 功能特性 | Feature | 详情页「功能特性」区块的一条 | 与版本无关，属软件级 |
| 截图 | Screenshot | 软件 / 插件的展示图 | 只存 URL，仓库不放图片文件 |

### 2.2 插件

| 术语 | 英文 / 标识 | 含义 | 易混点 |
| --- | --- | --- | --- |
| 插件 | Plugin / `plugin` | 社区作者提交、可被桌面端安装的一个 `.zip` 包 | 站点统一叫**插件** |
| 卡带 / 子程序 | —— | 桌面端 UI 里对已安装插件的称呼 | **同一个东西的两个视角**：站点叫插件，桌面端货架上叫卡带 |
| 内置插件 | —— | `calculator` / `fast-txt` / `task` / `fast-cmd` | 这四个 ID 是保留字，社区**永远不得**覆盖 |
| 插件 ID | `plugin_id` | `manifest.json` 的 `id`，全局唯一，正则 `^[a-z0-9][a-z0-9-]{0,63}$` | ≠ 数据库主键 `id`，≠ URL 用的 `slug` |
| 清单 | manifest / `manifest.json` | 插件描述文件，必须位于 zip 根目录 | 允许多套一层唯一目录 |
| 入口 | `entry` | 插件启动文件，必须是存在的 `.html` 或 `.js` | |
| 权限 | `permissions` | `storage` / `messaging` / `notifications` / `clipboard` | 站点只做展示与校验，不代桌面端授权 |

### 2.3 技术与状态

| 术语 | 含义 | 易混点 |
| --- | --- | --- |
| 发布态 | `software.status` / `software_release.status`：`0` 草稿、`1` 已发布 | 与"审核态"是**两套** |
| 审核态 | `plugin.status`：`0` 待审、`1` 已上架、`2` 已驳回、`3` 已下架；`plugin_release.status`：`0` 待审、`1` 通过、`2` 驳回 | 见 §4.4 状态机 |
| 账号状态 | `users.status`：`3` 超管、`2` 管理员、`1` 普通用户、`-1` 用户禁用、`-2` 管理员禁用 | **负数也表示启用中的禁用态**，不是"已删除" |
| 票据 | ticket | 5 分钟有效的 OSS 预签名地址，登录换取 | 只用于软件安装包 |
| 稳定下载地址 | —— | `/plugin/{slug}/download`，302 到公共桶，URL 不随换包变化 | 插件专用，匿名可访问 |
| 对象键 | `object_key` | OSS 对象键，**不含域名** | 数据库绝不存直链 |
| 底座 / 骨架 | `15-hundun` | 本项目的开发底座（账号 + 管理 + 安全壳子） | 不是"馄饨桌面" |
| 镜像模式 | —— | 桌面端 A/B 双会话并行能力 | 站点不涉及，不要在站点文档中引用 |

## 3. 角色与权限矩阵

账号角色由 `users.status` 决定（详见[数据字典 §枚举字典](03-数据字典.md#5-枚举字典)）。

| 能力 | 游客 | 普通用户(1) | 管理员(2) | 超级管理员(3) |
| --- | --- | :-: | :-: | :-: | :-: |
| 浏览首页 / 软件列表 / 软件详情 | ✅ | ✅ | ✅ | ✅ |
| 浏览插件列表 / 详情 | ✅ | ✅ | ✅ | ✅ |
| **下载插件 zip** | ✅ | ✅ | ✅ | ✅ |
| **下载软件安装包** | ❌ `AUTH_NOT_LOGGED_IN` | ✅ | ✅ | ✅ |
| 注册 / 登录 / 改自己资料 | ➖ | ✅ | ✅ | ✅ |
| 提交插件 | ❌ | ✅ | ✅ | ✅ |
| 查看"我的插件"、重新提交 | ❌ | ✅（仅本人） | ✅ | ✅ |
| 审核 / 下架插件 | ❌ | ❌ | ✅ | ✅ |
| 后台录入软件、发版本、传安装包 | ❌ | ❌ | ✅ | ✅ |
| 查看后台下载数据 | ❌ | ❌ | ✅ | ✅ |
| 用户管理（禁用 / 删除普通用户） | ❌ | ❌ | ✅ | ✅ |
| 生成管理员邀请码、管理管理员 | ❌ | ❌ | ❌ | ✅ |
| 提交反馈 / 查看自己的反馈 | ❌ | ✅ | ✅ | ✅ |
| 处理反馈 | ❌ | ❌ | ✅ | ✅ |

补充规则：

- **禁用是即时的**：`-1` / `-2` 的账号在每次请求时都会被校验并吊销令牌，不需要等令牌过期。
- **没有内置管理员**：仓库不提供管理员账号，也不提供引导逻辑。需要用管理接口时，先注册，再手工把 `status` 改为 `2` 或 `3`（M1 会决定 `ADMIN_BOOTSTRAP_*` 是否取代这一步）。
- **默认拒绝**：后端 `AccessControlInterceptor` 是唯一放行决策点，未标 `@PublicApi` 的接口一律需要登录；`/admin/**` 前缀另加角色校验。

## 4. 业务流程

### 4.1 浏览与下载（正向）

```
游客打开 /software/{slug}
  → 后端返回双语内容（*_zh / *_en 两列）
  → 游客点「下载」
  → 前端检测未登录 → 弹登录框，并记住要下载的那个 assetId
  → 登录成功 → POST /download/ticket { assetId }
  → 后端校验「软件已发布 + 版本已发布 + 资产属于该版本」
  → 同一事务内：release_asset.download_count++ 且写 download_record
  → 返回 { url, fileName, fileSize, sha256, expiresIn:300 }
  → 浏览器直连 OSS，文件不经过应用服务器
```

**反向分支**

| 情况 | 结果 |
| --- | --- |
| 未登录点下载 | `401 AUTH_NOT_LOGGED_IN`，前端弹登录框（不是跳登录页，保住当前上下文） |
| 资产不存在 / 未发布 | `404 DOWNLOAD_ASSET_NOT_FOUND` |
| OSS 未配置 | `503 DOWNLOAD_STORAGE_UNAVAILABLE`（宁可明确报错，不返回"点开就 404 的假地址"） |
| 60 秒内请求超过 30 次 | `429 RATE_LIMITED` |
| 令牌过期 | `401 AUTH_TOKEN_EXPIRED`，前端清会话并弹登录 |

### 4.2 注册与登录

- 五种登录方式：用户名+口令、手机号+口令、邮箱+口令、邮箱验证码（先 `/email-code/send` 再 `/email-code`）、注册。
- 注册一律产出普通用户（`status=1`）；管理员注册需要邀请码（`/user/register/admin`）。
- 登出会立即吊销 Redis 中的令牌，不是"等它自己过期"。
- 失败提示统一（防账号枚举）：注册冲突返回 `USER_ALREADY_EXISTS`「注册信息不可用」，不透露是用户名还是邮箱被占。

### 4.3 发一个版本（M1）

```
后台新建/编辑软件（草稿）
  → 新建版本（version + channel + 双语更新说明；published_at 为空 = 未发布）
  → 上传安装包（platform/arch/package_type + 文件）→ 流式转存私有桶 + 算 sha256
  → 发布版本（status=1）
  → 前台详情页出现下载按钮（无需改代码、无需重新发版）
```

### 4.4 插件提交与审核（M2）

```
登录用户上传 .zip → (0)待审
   │
   ├─ 管理员通过 → (1)已上架 → 公开可见、匿名自由下载
   │                    └─ 管理员可下架 → (3)已下架（前台 404、短链失效）
   └─ 管理员驳回 → (2)已驳回 → 作者看到 review_note → 修改后重新提交 → 回到 (0)待审

更新版本：新建一条 plugin_release(status=0)；
          插件页继续展示上一个已通过版本，新版本过审后才成为「最新版」。
```

**反向分支**：上传被拒的错误码见[接口文档 §错误码](04-接口文档.md#4-错误码总表)（`PLUGIN_*` 系列），前端只做礼貌预检，判定权在服务端。

## 5. 业务不变量（硬规则）

以下任何一条被破坏，都应视为 bug 而不是"优化"：

| # | 不变量 | 位置 |
| --- | --- | --- |
| I1 | 站点不写死任何软件信息；新增/修改内容只改数据，不改代码 | 全站 |
| I2 | 最新版不落冗余标记，按 `(software_id, channel)` 的 `published_at` 倒序推导 | `software_release` |
| I3 | 软件安装包所在桶必须**私有读**；若公开读，"登录才能下载"就只是装饰 | OSS / `release_asset` |
| I4 | 插件 zip 走**公共读**（社区传播优先），但仍保留稳定短链以便计数 | `plugin_release` |
| I5 | 数据库只存 `object_key`，绝不存带域名的直链 | 全部资产 |
| I6 | 下载明细写入与 `download_count` 自增在同一事务内 | `download_record` |
| I7 | IP 只存 SHA-256 摘要，User-Agent 截断到 255 字符 | `download_record` |
| I8 | 仓库内不含任何用户数据行、安装包、截图文件 | 仓库 / `db/` |
| I9 | 错误码（`errorCode`）稳定不变；后端只返回码，文案由前端按语言翻译 | `ErrorCode` / i18n |
| I10 | 内容字段成对存放（`*_zh` / `*_en`），接口一次返回两列，切语言不重新请求 | 全部内容表 |
| I11 | 界面文案走 vue-i18n，组件内禁止出现 CJK 字面量（由 `check-i18n.mjs` 守） | 前端 |
| I12 | 色值只在 `styles/tokens.css` 出现一次，组件与 scoped 样式禁止色值字面量 | 前端 |
| I13 | 内置插件 ID（`calculator`/`fast-txt`/`task`/`fast-cmd`）不可被社区覆盖 | 插件校验 |
| I14 | 插件更新版本 = 新 `plugin_release` 记录重新进审，不覆盖旧版本 | 插件审核 |
| I15 | SQL 脚本只增不改：`01_schema.sql` 的既有列语义不得变更，新结构走 `1x_*.sql` | `db/` |
| I16 | 所有 SQL 脚本幂等，可重复执行 | `db/` |
| I17 | 敏感配置全部走环境变量，`application-secret.yml` 已被 gitignore | 后端 |
| I18 | 前端存储键统一前缀 `hundunlab.`（M0 清理旧 `token` 键） | 前端 |
| I19 | 每次提交双推：`origin`（gitee `chaos-lab`）+ `github`（`Hundun-Lab`） | 仓库 |

## 6. 易错点速查

| 现象 | 真正原因 |
| --- | --- |
| 详情页没有下载按钮 | 种子数据里 `release_asset` 为空——**是数据缺失，不是页面坏了** |
| 未登录点下载返回 401 | 设计如此，前端应弹登录框而非跳登录页 |
| `/admin/**` 返回 `AUTH_FORBIDDEN` | 账号 `status` 不是 2 或 3 |
| 改了组件页面没变化 | Vite 偶发缓存旧 SFC，重启 dev server |
| `pnpm install` 后 Vite 报找不到 rollup | 锁文件是 pnpm 9 格式，别用 pnpm 12 |
| 切语言还有中文 | 数据库 `*_en` 列为空（`localized()` 会回落中文） |
| 令牌"登出了还能用" | 检查 Redis 是否可用；Redis 故障时会降级为仅验签，吊销失效 |
