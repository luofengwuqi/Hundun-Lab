## 1. 产品定位与范围

### 1.1 一句话定位

馄饨系列软件的官方站点：**展示项目、分发安装包、承载各软件的扩展**，视觉上与桌面端同一套语言。
（`[已确认]` D001、D003；扩展模型见 D071–D086）

### 1.2 三条不妥协的约束

1. **数据驱动**：软件、版本、安装包、扩展全部来自数据库，新增内容不改代码。（`[文档既定]` S03 不变量 I1；最初由 S02 §3 确立）
2. **家族的视觉**：浅色（朱红 `#C3272B` + 米白 `#FFF8E8`）／深色（馄饨绿 `#00FF88` + 馄饨黑 `#141414`）双主题；页面版式自由，色值只能来自令牌。（`[已确认]` D009、D023、D078、D079、D080）
3. **契约冻结**：`{ code, errorCode, message, data }` 与 `errorCode` 枚举不因重构而变。（`[已确认]` D049）

## 2. 用户、权限与核心术语

### 2.1 角色

| 角色 | 判定 | 能做什么 |
| --- | --- | --- |
| 游客 | 未登录 | 浏览全部前台页面、**匿名下载扩展 zip** |
| 普通用户 | `users.status = 1` | 游客权限 + 登录 / 改资料 / 下载安装包 / 提交扩展 / 看我的扩展 |
| 管理员 | `status = 2` | 普通用户权限 + 后台录入与发版 + 审核 / 下架扩展 + 下载数据 |
| 超级管理员 | `status = 3` | 管理员权限 + 生成邀请码、管理管理员 |

完整权限矩阵见 `docs/02-术语与业务规则.md` §3，此处不复述。（`[文档既定]`）

### 2.2 术语

只列本 PRD 反复使用的五个；其余见 `docs/02` §2。

| 术语 | 含义 | 易混点 |
| --- | --- | --- |
| 软件 / Software | 馄饨系列的一个产品，当前仅 HundunDesktop 上架，**模型必须支持多软件**（D086） | ≠ 扩展 |
| 版本 / Release | 某软件的一个版本，由 `version` + `channel` 唯一确定 | 没有 `is_latest` 字段，最新版按 `published_at` 推导（D064） |
| 安装包 / Asset | 一个版本下「平台 + 架构 + 格式」的具体文件 | ≠ 版本 |
| 扩展 / Extension | **某个软件**的可安装增量（当前形态是 `.zip`），`software_id` 必填（D071、D072）。不是所有软件都有扩展（D073） | 数据层统一叫扩展；Desktop 的 UI 文案叫"插件"，桌面端货架上叫"卡带"——三个词指同一物 |
| 卡带 / Cartridge | **本文档中专指视觉语言**：八边形切角 + 斜纹 + 硬侧面的展示卡，**止步于 HundunDesktop**（D077） | 与"扩展"的别名"卡带"不是一回事，注意上下文 |

> 最后一个歧义必须记住：D035 里的"卡带"是视觉组件；`docs/02` 里的"卡带"是桌面端对已安装扩展的称呼。
> 2026-11-05 起，数据层与本文档统一用**扩展**，"插件"只作为 HundunDesktop 界面上的文案（D071）。

## 4. 前台功能规格

> 本节含 F01–F11 与 F16；后台的 F12–F15 见 §5。
> F16（桌面端对接）放在本节，因为它属于站点对外能力，且前提是 F10 先可用；编号不按章节顺序排列，按领域排列。

### F01 站点框架与设计系统

- **使用者**：全体访客
- **前置条件**：无
- **主流程**：
  1. 进入任一页面，得到统一页头（图形标 + 字标 + 三项导航 + 主题按钮 + 中/EN + 用户胶囊）与页脚
  2. 切换主题：写入 `hundunlab.theme`，`data-theme` 立即生效，无闪烁
  3. 切换语言：`zh` / `en`，内容字段一次取回两列，不重新请求
  4. 375px 宽下出现汉堡菜单，抽屉可开可关
- **异常流程**：
  - `localStorage` 不可用 → 回落馄饨黄，不报错
  - 接口失败 → 错误态（错误码 → i18n 文案 → 重试按钮）
  - 首屏前出现未主题化闪白 → 视为缺陷（D061 要求内联脚本先设 `data-theme`）
- **业务规则**：D009／D023／D039／D043／D044／D057／D058／D061／D062
- **可配置边界**：导航项、语言项、主题项来自配置常量，不散落在模板里；色值只来自令牌
- **关联决策**：D009、D023、D039、D043、D044、D057、D058、D061、D062

### F02 首页

- **使用者**：游客与登录用户
- **前置条件**：至少 1 个已发布软件（当前恰好 1 个，见 `00-CONTEXT` §4）
- **主流程**：
  1. 首屏：标题「一些工具，一些新可能」+ 两行副文 + 主按钮「探索软件」+ 次链接「实验室进行中」+ 三项实验室指标
  2. 右侧：四块工具瓦片（窗口／准星／叉／网格）+ 积木塔 + 图注 `TOOLS / IDEAS / EXPERIMENTS`
  3. 「软件与实验」区：主卡（HundunDesktop，卡带样式、红胶带、折角、掌机插画越出卡底）+ 两张实验卡（实验中／探索中）
  4. 页脚单行
- **异常流程**：
  - 无已发布软件 → 展示空文案，不留空白卡（不再指向扩展页，扩展已无站点级入口，D074）
  - `GET /software` 失败 → 错误态 + 重试；不得退回硬编码假数据
  - 实验卡为"预告"性质，点击不得进入 404
- **业务规则**：D034（结构可扩展到第 3 个及以后软件）、D035（卡带限 Desktop）、D036（指标口径）、D037（扉页排版型，无插画）、D045（版式对齐参考图、配色走全站令牌）
- **可配置边界**：三项指标、实验卡数量与文案，M0 写死，M1 起改为后台常量（Q006 待定）
- **关联决策**：D034–D037、D045、Q004、Q005、Q006

### F03 软件列表

- **使用者**：访客
- **前置条件**：无
- **主流程**：进入 `/software` → 卡片网格（封面／名称／一句话／平台／下载量）→ 点卡片进详情
- **异常流程**：无数据 → `EmptyState`（说明 + 行动按钮）；加载 → 骨架屏（非转圈）；失败 → 错误态 + 重试
- **业务规则**：只展示 `status = 1` 的软件；排序按后台 `sort_order`
- **可配置边界**：每页条数、排序权重由后台控制
- **关联决策**：D019、D034、D035

### F04 软件详情

- **使用者**：访客
- **前置条件**：软件已发布
- **主流程**：名称／标语／介绍（Markdown）→ 功能特性 → 截图 → 平台 → 版本表 → 主下载按钮
- **异常流程**：slug 不存在或未发布 → 404 页 + 返回软件列表；资产缺失 → 下载按钮置灰并提示"暂无安装包"（不是页面报错，见 `docs/02` §6）
- **业务规则**：最新版按 `published_at` 推导（D064）；双语字段一次返回
- **可配置边界**：特性／截图／平台的条目数与顺序均由后台整块替换
- **关联决策**：D019、D038（本轮不改结构）、D064
- **备注**：与首页 hero 曾逐字节相同，重构后必须保持结构级差异（D038）

### F05 账号与登录

- **使用者**：游客、登录用户
- **前置条件**：无
- **主流程**：
  1. 五种登录：用户名+口令、手机号+口令、邮箱+口令、邮箱验证码（先发码再登录）、注册
  2. 登录成功后写 `hundunlab.token`，回到来源页
  3. 从下载按钮触发的登录，成功后自动续传该次下载
- **异常流程**：
  - 注册冲突 → `USER_ALREADY_EXISTS`「注册信息不可用」，**不透露**是用户名还是邮箱被占（防账号枚举）
  - 令牌过期 → 清会话 + 弹登录
  - 登录框需支持 ESC 关闭、焦点入框、关闭后焦点归还、`aria-modal`
- **业务规则**：注册一律产出 `status = 1`；管理员注册需邀请码；登出立即吊销 Redis 令牌
- **可配置边界**：验证码有效期与发送频率由后端常量控制
- **关联决策**：D049、D060、D070、Q002

### F06 安装包下载

- **使用者**：登录用户（游客触发则先弹登录）
- **前置条件**：软件已发布 + 版本已发布 + 资产属于该版本
- **主流程**：
  1. 点下载 → 未登录则弹登录框（**不跳页**）并记住 assetId
  2. 登录后 `POST /download/ticket` → 拿到 5 分钟预签名地址
  3. 浏览器直连 OSS，文件不经过应用服务器
  4. 同事务内 `release_asset.download_count++` 且写 `download_record`
- **异常流程**：
  - 未登录 → `401 AUTH_NOT_LOGGED_IN`
  - 资产不存在／未发布 → `404 DOWNLOAD_ASSET_NOT_FOUND`
  - OSS 未配置 → `503 DOWNLOAD_STORAGE_UNAVAILABLE`（宁可明确报错，不给假地址）
  - 60 秒内 >30 次 → `429 RATE_LIMITED`
- **业务规则**：安装包桶必须私有读（D050）；DB 只存 `object_key`（D055）；IP 存哈希、UA 截断 255
- **可配置边界**：票据有效期、限流阈值走配置，不写死在前后端代码里
- **关联决策**：D015、D021、D050、D055、D060、O02

### F07 扩展市场（软件详情页内）

- **使用者**：访客
- **前置条件**：该软件**有**已上架扩展（`extension WHERE software_id = ? AND status = 1` 计数 > 0，D073）。计数为 0 时整个分区不渲染，不留空容器
- **主流程**：软件详情页 `#extensions` 分区 → 精选卡 ≤ 6 个（图标／名称／作者／版本／下载量）→「查看全部」内联展开（前端过滤 + 本地分页，**不换页**，D074）→ 点卡进扩展详情
- **异常流程**：无已上架扩展 → 分区不渲染；接口失败 → 分区内错误态 + 重试，**不影响页面其余部分**
- **业务规则**：只展示 `status = 1`；精选排序为 `featured DESC, download_count DESC`；内联展开后每页 12 个；分区标题文案为「扩展」，HundunDesktop 页面上写「插件」
- **可配置边界**：精选卡数（默认 6）、内联每页条数（默认 12）、分区锚点 id（`extensions`）
- **关联决策**：D071、D073、D074、D077；原 D003、D019、D020 的"插件列表"语义由 D074 收窄

### F08 扩展详情

- **使用者**：访客
- **前置条件**：扩展已上架，且**属于 URL 中 `:slug` 所指的软件**（不匹配一律 404，防止跨软件串门，D072）
- **主流程**：`/software/:slug/extensions/:id` → 图标／名称／作者／`author_type` 徽章／最新版本／版本历史／权限标签／平台／截图／README（Markdown）／下载按钮 → 面包屑回到 `/software/:slug#extensions`
- **异常流程**：未上架或已下架 → 404（含直链）；`software_id` 不匹配 → 404；README 为空 → 不渲染空容器
- **业务规则**：**社区扩展**固定显示风险提示"插件由社区作者提供，请自行评估安全性"（中英双语，D065）；**官方扩展**显示「官方提供」徽章且**不显示**该提示（D083、Q007 待定稿）；`permissions` 原样展示；展示 `sha256` 前 12 位
- **可配置边界**：风险提示文案可改，但不可删除
- **关联决策**：D020、D065、D083、D072

### F09 扩展提交与预检

- **使用者**：登录用户
- **前置条件**：已登录；目标软件存在
- **主流程**：
  1. 从 `/software/:slug#extensions` 底部「提交扩展」进入 `/software/:slug/extensions/submit`（URL 携带软件上下文，D075）
  2. 拖拽 `.zip` → 前端 4 项礼貌预检（大小 ≤ 20MB／魔数 `PK\x03\x04`／manifest 存在／id 合法）
  3. 填写中英简介、README、图标、颜色
  4. 提交 → 进入 `(0) 待审`
- **异常流程**：预检不过 → 就地提示且不发起请求；服务端拒 → 按 `EXTENSION_*` 错误码显示具体原因（不显示"上传失败"这种无信息文案）
- **业务规则**：判定权永远在服务端（D051）；六层校验顺序固定；内置 ID 四个保留（D053、D085）；同软件下同扩展版本号不可重复；**官方扩展不在本页提交**，走后台（D084）
- **可配置边界**：20MB／2000 条／50MB／100:1／5 次每小时 均为服务端配置项（D052）
- **关联决策**：D020、D051、D052、D053、D084、D085

### F10 扩展下载短链

- **使用者**：任何人（含未登录）
- **前置条件**：扩展已上架 + 版本已通过
- **主流程**：`GET /software/{slug}/extensions/{id}/download[?version=]` → 计数（同事务，写 `extension_download`）→ 302 到公共桶
- **异常流程**：未上架／已下架 → 404；超频 → 429
- **业务规则**：URL 不随换包变化（D021、D054）；公开读（D015）；内置／官方扩展与社区扩展**下载链路完全一致**（D085）
- **可配置边界**：60 次/分钟/IP 限流（D052）
- **关联决策**：D015、D021、D050、D054、D085

### F11 我的扩展

- **使用者**：登录用户
- **前置条件**：已登录
- **主流程**：`/user/info` → 基本资料（只读为主）+ 我的扩展列表（软件名／扩展名／版本／状态徽标／驳回原因／操作）
- **异常流程**：无扩展 → 空态，引导去对应软件的详情页（**不直连上传页**，因为提交必须先选定软件）；驳回后重新提交 → 回到待审
- **业务规则**：只能看本人的扩展；状态徽标对应四态；列表按软件分组
- **可配置边界**：列表排序（默认最近更新）
- **关联决策**：D024、D066、D075

### F16 桌面端对接（M3，`[后续]` 至 M2 完成）

- **使用者**：桌面端用户
- **前置条件**：F10 可用；站点有稳定域名
- **主流程**：桌面端 ADD → 逛逛社区 → 官网 `/software/hundundesktop/extensions` → 下载 zip → 返回桌面端安装 → 卡带出现在货架 → 启动
- **异常流程**：域名未就绪 → 保持跳转 Gitee 仓库（当前行为），不得出现死链
- **业务规则**：`COMMUNITY_URL` 指向 `https://<域名>/plugins`；安装规则以 `chaos-lite/docs/PLUGIN_SPEC.md` 为唯一事实源，站点只转述
- **可配置边界**：无（硬编码常量，随发版改）
- **关联决策**：D002、O01

  3. 发布版本 → 前台详情页出现下载按钮
- **异常流程**：上传中断 → 不留半截对象；OSS 未配置 → 明确报错；删除资产 → 连带删 OSS 对象
- **业务规则**：`published_at` 决定最新版（D064）；版本号 + channel 唯一
- **可配置边界**：安装包大小上限（`UPLOAD_MAX_FILE_SIZE` 只管扩展 zip，安装包走流式不受此限）
- **关联决策**：D013、D048、D064、O02

### F14 下载数据概览

- **使用者**：管理员
- **前置条件**：有下载记录
- **主流程**：总下载量、按软件、按平台、近 30 天趋势
- **异常流程**：无数据 → 显示 0 与空图，不显示 "NaN"
- **业务规则**：只读，不提供导出（本期）
- **可配置边界**：统计口径固定为 `download_record` 计数
- **关联决策**：D013

### F15 扩展审核

- **使用者**：管理员
- **前置条件**：有 `status = 0` 的扩展
- **主流程**：
  1. 列表：待审优先，可按**软件**与状态筛选，按 `author_type` 分列（`official` / `community`），行内通过／驳回
  2. 详情：manifest 摘要（id/name/version/权限/窗口尺寸/平台）、zip 内容清单、README 预览
  3. 通过 → `1`；驳回 → `2` 且**必填原因**（≤500 字）
  4. 已上架可下架（`3`），下架后前台 404 且短链失效
  5. **官方扩展发布**：管理员可上传新包（不经前台上传表单），进审后同样走 1–3（D084）
- **异常流程**：非法状态迁移 → `EXTENSION_STATUS_CONFLICT`；驳回不填原因 → 前端阻止提交 + 后端拒绝
- **业务规则**：通过／驳回同时更新 `extension.status` 与对应 `extension_release.status`；官方扩展与社区扩展走**同一套**审核状态机，不设第五态（D083）
- **可配置边界**：原因长度上限 500
- **关联决策**：D020、D066、D083、D084、Q003

## 7. 核心状态与边界

### 7.1 扩展状态机

```
                提交(.zip)                     通过
   [无] ───────────────▶ (0)待审 ──────────────▶ (1)已上架 ──下架──▶ (3)已下架
                          │  ▲                     ▲                    │
                     驳回 │  │ 修改后重提            │ 恢复                │
                          ▼  │                     └────────────────────┘
                        (2)已驳回
```

- 版本级另有 `extension_release.status`：`0 待审 / 1 通过 / 2 驳回`。
- **官方扩展不走 `[无] → (0)` 这条边**：种子数据直接落 `(1)`，后续换包从 `(1)` 回到 `(0)` 重新进审（D083、D084）。
- 更新版本 = 新建 `plugin_release(status=0)`；过审前展示上一个已通过版本（D054）。

### 7.2 软件发布态

`software.status` / `software_release.status`：`0` 草稿、`1` 已发布。与审核态是两套，不要混用。

### 7.3 边界与上限

| 项 | 值 | 依据 |
| --- | --- | --- |
| 扩展 zip 大小 | ≤ 20 MB | D052 |
| zip 条目数 | ≤ 2000 | D052 |
| 解压总量 | ≤ 50 MB | D052 |
| 压缩比 | ≤ 100:1 | D052 |
| 提交频率 | 5 次/小时/账号 | D052 |
| 短链限流 | 60 次/分钟/IP | D052 |
| 下载票据 | 5 分钟有效，30 次/分钟 | D052 |
| 驳回原因 | ≤ 500 字 | D066 |

### 7.4 极端场景

- OSS 不可用：下载类接口返回 `503`，页面显示"存储暂不可用"，**不返回假地址**。
- Redis 不可用：令牌吊销失效，降级为仅验签；此时登出不能立即生效（已在 `docs/02` §6 记录）。
- 并发下载计数：`download_count` 自增与明细写入同事务（不变量 I6）。

### F08 扩展详情

- **F08-01** 访问已下架扩展的 URL 返回 404。
- **F08-02** 社区扩展页面固定出现风险提示（中英各一），且 `permissions` 原样列出。
- **F08-03** 页面展示的 `sha256` 前 12 位与数据库中该版本记录一致。
- **F08-04** 用软件 A 的 URL 前缀去访问软件 B 的扩展 id，返回 404（不是 403、不是错乱展示）。
- **F08-05** 官方扩展显示「官方提供」徽章且**不显示**社区风险提示。

### F09 扩展提交

- **F09-01** 上传 21MB 的 zip，前端就地拒绝，网络面板无提交请求。
- **F09-02** 上传无 `manifest.json` 的 zip，返回 `EXTENSION_MANIFEST_INVALID` 并展示具体原因。

- **F09-05** 同一扩展重复上传相同版本号，返回 `EXTENSION_VERSION_EXISTS`。

### F10 扩展下载

- **F10-01** 未登录直接访问 `/software/{slug}/extensions/{id}/download`，得到 302 且能下到文件，计数 +1。
- **F10-02** 发布新版本后，同一个短链下载到新文件，URL 未变。
- **F10-03** 60 秒内请求 61 次，第 61 次返回 429。
- **F10-04** 官方扩展与社区扩展的下载链路一致：两者都返回 302 且都计数。

### F11 我的扩展

- **F11-01** 用户 A 登录后看不到用户 B 的扩展（直接构造 B 的扩展 id 请求亦返回 403）。
- **F11-02** 被驳回的扩展显示驳回原因与"重新提交"按钮，重新提交后状态回到待审。
- **F11-03** 列表按软件分组；无扩展时的空态里**没有**直连上传页的入口（必须先选软件）。

### F12 后台软件管理

- **F12-01** 从空库开始，仅通过后台创建一条软件（含 2 特性、1 截图、1 平台），前台列表与详情立即可见。
- **F12-02** 用重复 slug 新建，提示冲突且已填内容不丢失。
- **F12-03** 下线软件后，前台列表不再出现，直链访问详情返回 404。

### F13 版本与安装包

- **F13-01** 上传安装包后，`release_asset.sha256` 与本地 `sha256sum` 结果一致。
- **F13-02** 版本不设 `published_at`（未发布）时，前台详情不出现该版本与下载按钮。
- **F13-03** 删除资产后，OSS 上对应对象同时消失（用对象键查询返回 404）。

### F14 数据概览

- **F14-01** 执行 3 次真实下载后，概览总数增加 3，按软件与按平台的分布同步增加。
- **F14-02** 无任何下载记录时，概览显示 0 与空图，不出现 `NaN` 或报错。

### F15 扩展审核

- **F15-01** 待审扩展在前台不可见（分区与直链都不可见）。
- **F15-02** 驳回不填原因时无法提交；填写后作者侧可见该原因。
- **F15-03** 通过后扩展公开可见且可匿名下载；下架后前台 404 且短链返回 404。
- **F15-04** 后台「官方扩展发布」上传的新包同样进入 `(0) 待审`，审核列表里 `author_type = official` 可辨识。
- **F15-04** 对已通过的版本再次执行"通过"，返回 `PLUGIN_STATUS_CONFLICT`。

### F16 桌面端对接

- **F16-01** 桌面端点"逛逛社区"落到官网 `/plugins`（域名未就绪时仍落 Gitee，不出现死链）。
- **F16-02** 从官网下载的 zip 能在桌面端安装成功，卡带出现在货架并可启动。
