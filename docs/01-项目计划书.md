## 0. 一页速览

**项目**：馄饨系列软件的官方站点 —— 展示项目、分发安装包、承载插件社区。

**当前状态**：阶段 1 前台已上线可跑（首页 / 软件列表 / 软件详情 / 登录 / 需登录的下载），
后端骨架（鉴权双通道、下载票据、双语内容模型）就位；**管理后台、插件社区、桌面端对接全部未开始**。
前端处于"两代共存"状态，74% 为不可达死代码，需要一次彻底清场 + 双主题换肤。

**四个里程碑（串行）**

| 里程碑 | 一句话 | 完成即意味着 |
| --- | --- | --- |
| **M0** 前台全量重构 | 设计图 → HTML 原型 → 落地 Vue | 站点长成馄饨的样子，且不再有死代码 |
| **M1** 管理后台 + 上线 | 内容运营三件套 + 部署 | 发新版本只录数据、不改代码 |
| **M2** 插件社区 | 上传 / 审核 / 稳定下载 | "社区计划"第一次真正落地 |
| **M3** 桌面端对接 | `COMMUNITY_URL` 切换 + 安装联调 | 官网与 HundunDesktop 形成闭环 |

**三条不妥协的约束**

1. **数据驱动**：软件、版本、安装包、插件全部来自数据库，新增内容不改代码。
2. **家族的视觉**：馄饨黄 / 馄饨黑双主题 + 复古掌机像素风，与桌面端同一套语言。
3. **契约冻结**：`{ code, errorCode, message, data }` 与 `errorCode` 枚举不因重构而变。

**本计划不覆盖**：评分评论、插件签名、热更新、付费、SSR、第二个产品上架（详见 §3.2）。

### 2.2 前端审计结论（决定"改写程度"）

审计以 `src/main.js` 的 import 图为准，结论如下：

| 事实 | 数字 |
| --- | --- |
| 前端总规模 | 61 文件 / 10,531 行（vue+js+css） |
| **不可达死代码** | **39 文件 / ≈7,790 行（74%）** |
| 死代码重灾区 | `views/admin`(8 个, 3,331 行)、`views/user`(7 个, 1,687 行)、`views/login`(7 个, 1,260 行)、`views/help`(5 个, 974 行) |
| 旧层硬编码中文 | 380 处用户可见字符串（新层模板仅 1 处，为语言按钮「中」，属故意） |
| 旧层 `<el-*>` 标签 | 170 个，且全工程无 `app.use(ElementPlus)` —— 挂上路由也渲染不出来 |
| 死依赖 | `element-plus`、`@element-plus/icons-vue`、`less`、`marked`（只有旧层引用） |
| 旧资源 | `assets/img/` 13 张图 / 1.4MB，全部只服务旧视觉 |
| lint 流水线 | **坏的**：脚本调 `eslint`，但 eslint 未安装、无 `eslint.config.*`；oxlint 未安装 |
| 新层质量 | 下载票据续传、错误码 i18n 回落、三态、`minmax(0,1fr)` 等细节正确；但样式为单主题、散落 16 处硬编码色值、无 Press Start 2P 字体、移动端导航直接 `display:none` |

**据此确定的改写程度（三句话）：**

1. **旧层整层删除**（27 个视图 + 旧 api/stores/utils + 13 张旧图 + 4 个死依赖）——"重构"的大头其实是清场。
2. **新层基础设施与页面逻辑保留**：`api/http.js`（ApiError 契约）、`api/site.js`、`stores/session.js`、`i18n/*`、`router`、下载门与三态逻辑——这些是验证过的正确设计，推倒只会把踩过的坑再踩一遍。
3. **样式体系按双主题 token 重做**：`site.css` 单主题架构换成 `tokens.css` + `[data-theme]`，收敛硬编码色，重画首页掌机 hero，引入自托管像素字体。

> 按行数存活率约 20–25%，但活下来的覆盖全部基础设施与核心页面逻辑。
> 骨架评审 R8 的"整站重写 10–12 人日"是对**旧层**的判断，那一层已被新层取代，不必再付一次。

## 3. 目标与非目标

1. 站点视觉与交互达到"能作为馄饨系列官方门面"的水准（双主题、像素、全端可用）。

## 4. 设计系统（双主题）

### 4.1 主题机制

- 两套官方主题：**馄饨黄**（默认，浅色国风）/ **馄饨黑**（深色霓虹），命名与桌面端对齐。
- 切换方式：`document.documentElement.dataset.theme = 'hun-tun-yellow' | 'hun-tun-dark'`，
  持久化键 `hundunlab.theme`；**默认恒为馄饨黄，不跟随系统**（品牌优先）。
- 所有色值只在 `frontend/src/styles/tokens.css` 出现一次；组件与 scoped 样式只允许引用变量，
  禁止 `#hex` / `rgba()` 字面量（`check-i18n.mjs` 同目录再加一个色值扫描脚本，防回归）。


### 4.2 使用规则

| 元素 | 规则 |
| --- | --- |
| 标题 / kicker / 卡带标签 | 像素字体 **Press Start 2P**（自托管 woff2），中文回落到系统无衬线；**仅限标题与标签**，正文绝不用 |
| 正文 | 系统字体栈：`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` |
| 卡片 | `--bg-card` 底 + 2px `--border` 边 + 4px 硬阴影（无模糊），圆角 ≤ 8px |
| 按钮 | 主按钮 `--accent` 底；次按钮描边；hover 加 `--glow`，不用缩放动画 |
| 扫描线 | 全站背景伪元素，`opacity: var(--scanline-opacity)`；后台页面关闭 |
| 插图/hero | 首页掌机壳用 CSS 绘制（沿用现有结构，按新 token 重画配色） |
| 图标 | 一律内联 SVG 或 CSS 形，不引图标库 |
| 动效 | 只允许 `transform` / `opacity`，`prefers-reduced-motion` 下全部关闭 |

## 5. 技术架构

### 5.1 总体

```
浏览器 ──HTTPS──▶ Nginx ─┬─ /            → frontend/dist（SPA，try_files 回退）
                          ├─ /api         → Spring Boot :5757
                          └─ /plugin/*/download → 后端 302 到公共桶

Spring Boot ─┬─ MySQL 8     （software / release / plugin / users / download_record …）
             ├─ Redis 6     （令牌吊销、验证码、限流计数）
             └─ 阿里云 OSS  ├─ 私有桶：安装包（预签名 5 分钟）
                            └─ 公共桶：插件 zip、截图、封面、头像
```

### 5.2 后端分层（沿用现状，不重排包）

```
com.hundunlab.site
├── common/     Result / ErrorCode / exception / context / util / constant
├── framework/  filter(TokenResolve) / interceptor(AccessControl) / aspect(RateLimit, RequireRole, AutoLog)
└── module/
    ├── auth/       登录注册登出、邮箱验证码
    ├── user/       资料、头像（M2 补"我的插件"聚合查询）
    ├── software/   软件、特性、截图、平台、版本、资产（M1 在此扩管理接口）
    ├── download/   票据、计数、明细（M1 加统计）
    ├── plugin/     ★ M2 新增：插件、版本、提交、审核、下载
    ├── admin/      账号与权限（仅此职责，不收敛业务管理）
    └── feedback/   M3 之后迁出（本期不动）
```

**决策**：管理接口不进 `admin` 模块，而是各业务模块内建 `AdminXxxController`（如 `module/software/controller/AdminSoftwareController`），
`admin` 模块只留账号/邀请/权限。理由：按领域聚合，删一个业务模块不会留下孤儿接口；`/admin/**` 前缀由拦截器统一兜底鉴权。
**不拆 `release` 独立模块**（评审曾建议）：现有 `ReleaseMapper` 已在 `software` 模块内，M1 的体量不值得再搬一次包。

```

├── main.js / App.vue
├── router/index.js            前台 + /user + /admin 三组路由（分组懒加载）
├── layouts/
│   ├── SiteLayout.vue         页头 + main + 页脚
│   └── AdminLayout.vue        M1：侧栏 + 内容区（紧凑变体，无扫描线）
```

## 9. M2 详细设计：插件社区

### 9.1 角色

| 角色 | 能力 |
| --- | --- |
| 游客 | 浏览插件列表/详情、**自由下载**（匿名） |
| 登录用户 | 上传插件、查看"我的插件"、重新提交 |
| 管理员（status=2/3） | 审核（通过/驳回）、下架/恢复、查看全部状态 |

### 9.2 状态机

```
                提交(.zip)                     通过
   [无] ───────────────▶ (0)待审 ──────────────▶ (1)已上架 ──下架──▶ (3)已下架
                          │  ▲                     ▲                    │
                     驳回 │  │ 修改后重提            │ 恢复                │
                          ▼  │                     └────────────────────┘
                        (2)已驳回
```

- 插件级 `plugin.status`：`0 待审 / 1 已上架 / 2 已驳回 / 3 已下架`。
- 版本级 `plugin_release.status`：`0 待审 / 1 通过 / 2 驳回`。
- **更新版本 = 新建一条 `plugin_release`（status=0）**，插件页继续展示上一个已通过版本；
  新版本过审后自动成为"最新版"，稳定下载地址不变。
- 任何状态变更写 `operation_log`（`module_name='plugin'`）。

### 9.3 页面

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/plugins` | 列表 | 搜索（名称/作者/ID）、排序（最新/最热）、分页 12/页 |
| `/plugins/:slug` | 详情 | 图标、作者、最新版本、版本历史、权限标签、平台、截图、README（Markdown 渲染）、下载按钮 |
| `/plugins/submit` | 上传 | 拖拽 .zip、前端先做 4 项预检（大小/魔数/manifest 存在/id 合法）、表单（中英简介） |
| `/user/info` | 我的插件 | 列表：名称/版本/状态徽标/驳回原因/操作（重新提交、查看详情） |
| `/admin/plugins` | 审核台 | 待审优先，可按状态筛选；行内通过/驳回 |
| `/admin/plugins/:id` | 审核详情 | manifest 摘要（id/name/version/权限/窗口尺寸/平台）、zip 内容清单、README 预览、通过/驳回（必填原因） |

### 9.4 上传与校验

服务端校验顺序（与桌面端 `plugin-installer.js` 一一对应）：

1. 请求层：登录、`@RateLimit`（5 次/小时/账号）、文件大小 ≤ 20MB。
2. ZIP 层：魔数 `PK\x03\x04`；加密包拒绝；条目数 ≤ 2000；解压总大小 ≤ 50MB；压缩比 ≤ 100:1；
   路径穿越（`..`、绝对路径、符号链接）拒绝；ZIP64 拒绝。
3. 结构层：根目录直接含 `manifest.json`（允许唯一一层包裹目录）；`entry` 存在且以 `.html`/`.js` 结尾。
4. Schema 层：`id` 匹配 `^[a-z0-9][a-z0-9-]{0,63}$`；`name` ≤ 32；`version` 语义化；`windowSize` 200–4000；
   `permissions ⊆ {storage, messaging, notifications, clipboard}`；`platforms ⊆ {win32, darwin, linux}`。
5. 业务层：`id` 不在内置保留列表（`calculator`/`fast-txt`/`task`/`fast-cmd`）；`id` 未被他人占用；版本号未重复。
6. 存储层：写入公共桶 `plugins/{plugin_id}/{version}/{file_name}`，回填 `sha256`、`file_size`、`manifest_json`。

前端只做"礼貌预检"（快速失败），**判定权永远在服务端**。

### 9.5 下载链路

```
GET /plugin/{slug}/download[?version=x.y.z]
  → 校验插件已上架 + 版本已通过
  → plugin.download_count++ / plugin_release.download_count++（同一事务）
  → 302 到公共桶 URL（稳定短链不随换包变化）
```

- 公开读，不要求登录（与安装包策略不同，明确取舍：社区传播优先）。
- 短链带 `@RateLimit`（60 次/分钟/IP），防刷计数。
- 详情页与列表页展示 `sha256` 前 12 位，供用户比对。

### 9.6 内容治理

- 审核必看：功能与描述一致、无恶意外联、无盗用资源、README 有实际说明。
- 驳回必须填原因（≤500 字），展示给作者。
- 详情页固定风险提示：**"插件由社区作者提供，请自行评估安全性"**（中英双语）。
- 内置 ID 永远不可被社区覆盖；`permissions` 原样展示给用户。

### 9.7 验收

见 §6.6。

```sql
  `created_at`     datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`     datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_plugin_slug` (`slug`),
  UNIQUE KEY `uk_plugin_pid` (`plugin_id`),
  KEY `idx_plugin_status_time` (`status`, `updated_at`),
  KEY `idx_plugin_author` (`author_user_id`),
  CONSTRAINT `fk_plugin_author` FOREIGN KEY (`author_user_id`) REFERENCES `users` (`id`) ON DELETE SET NULL

-- 插件版本：一次提交一条，更新版本 = 新增一条并重新审核
CREATE TABLE IF NOT EXISTS `plugin_release` (
  `id`              bigint       NOT NULL AUTO_INCREMENT,

  `file_size`       bigint       NOT NULL DEFAULT '0',

  `manifest_json`   json         DEFAULT NULL,
  `min_app_version` varchar(32)  DEFAULT NULL,
  `permissions`     json         DEFAULT NULL,
  `platforms`       json         DEFAULT NULL,
  `changelog`       text         COMMENT '本版说明',
  `status`          tinyint      NOT NULL DEFAULT '0' COMMENT '0-待审 1-通过 2-驳回',
  `download_count`  bigint       NOT NULL DEFAULT '0',
  `created_at`      datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_plugin_version` (`plugin_id`, `version`),
  KEY `idx_plugin_release_status` (`plugin_id`, `status`, `created_at`),
  CONSTRAINT `fk_plugin_release` FOREIGN KEY (`plugin_id`) REFERENCES `plugin` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='插件版本';

-- 插件截图
CREATE TABLE IF NOT EXISTS `plugin_screenshot` (
  `id`         bigint       NOT NULL AUTO_INCREMENT,
  `plugin_id`  bigint       NOT NULL,
  `image_url`  varchar(500) NOT NULL,
  `sort_order` int          NOT NULL DEFAULT '0',
  PRIMARY KEY (`id`),
  KEY `idx_plugin_shot` (`plugin_id`, `sort_order`),
  CONSTRAINT `fk_plugin_shot` FOREIGN KEY (`plugin_id`) REFERENCES `plugin` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='插件截图';
```

### 12.4 新增错误码

| errorCode | HTTP | 场景 |
| --- | --- | --- |
| `PLUGIN_ZIP_INVALID` | 400 | 魔数错、加密包、ZIP64、条目超限、解压超限、压缩比异常 |

| `PLUGIN_VERSION_EXISTS` | 409 | 同插件版本号重复 |
| `PLUGIN_NOT_FOUND` | 404 | 不存在或未上架/已下架 |
| `PLUGIN_NOT_OWNER` | 403 | 非作者操作 |
| `PLUGIN_STATUS_CONFLICT` | 409 | 非法状态迁移（如审核已通过的版本） |
| `PLUGIN_STORAGE_UNAVAILABLE` | 503 | OSS 未配置/不可用 |

## 15. 风险、依赖与待定

### 15.1 上线前置条件（时间不由开发决定）

| 条件 | 说明 | 责任 |
| --- | --- | --- |
| 域名 | 站点主域名（如 `hundunlab.xxx`） | 作者 |
| ICP 备案 | 国内服务器对外提供 HTTP 服务的前置要求，周期以周计 | 作者 |
| HTTPS 证书 | 备案后申请（或先用 IP + 自签做内网验收） | 作者 |
| OSS 双桶 | 私有桶（安装包）+ 公共桶（插件/图片），RAM 子账号最小权限 | 作者 |
| 发件邮箱 | `MAIL_FROM` / `MAIL_AUTH_CODE`（验证码与通知） | 作者 |

### 15.2 风险清单

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 域名/备案未就绪 | M1"上线"无法对外 | M1 以部署手册 + 内网/IP 验收为完成定义，域名后置 |
| 删旧层误伤可达代码 | 构建失败 | 删前 grep 校验引用；独立提交；构建与冒烟后再删 |
| 插件含恶意 JS | 用户损失、声誉 | 强制审核 + 风险提示 + 展示 permissions；签名列为后续 |
| 插件公开下载被刷 | 带宽成本 | 短链限流（60/min/IP）+ OSS 流量告警 + 可加 Referer 校验 |
| 双远端失同步 | 仓库分叉 | 每次提交双推；阶段完成核对 log |
| 桶权限配错 | 安装包裸奔/插件不可下 | 双桶隔离；上线检查单含"未签名直链访问应 403/200 分别校验" |
| 单点运维 | 宕机无人知 | M1 加 actuator 健康检查；后续接 Uptime 监控 |
| 增量脚本误改历史 | 环境漂移 | 不改 `01` 既有列语义；只加 `1x_*.sql`；空库回归 |

### 15.3 明确挂起（不在本期决策）

1. 插件签名与验签方案（等桌面端具备验签能力）。
2. 自动更新与设备令牌。
3. CDN 接入与防盗链策略。
4. 管理员引导方式（`ADMIN_BOOTSTRAP_*` 环境变量 vs 手工 SQL）——M1 实施时二选一。
5. 插件审核是否邮件通知作者（M2 可选，复用现有 SMTP）。
6. 后台视觉是否补充独立设计图（M1 沿用 tokens，必要时补 3 张关键页）。
